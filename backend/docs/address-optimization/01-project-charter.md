# 项目章程

## 1. 项目基本信息
- **项目名称**：收货地址优化 - 手机号回显 + 省市下拉选择
- **项目编号**：OM-ADDR-2026-001
- **项目经理**：AI Agent
- **发起人**：sunpeng
- **日期**：2026-05-30

## 2. 项目背景
当前收货地址表单中，省市区使用普通文本输入框，用户体验差；手机号输入缺少格式化和自动回显功能。需要优化为省市三级联动下拉选择，并增加手机号自动格式化功能。

## 3. 项目目标

### 3.1 业务目标
- 提升用户填写地址的效率和准确性
- 减少因手动输入导致的地址格式错误

### 3.2 技术目标
- 省市区从文本输入改为三级联动下拉选择
- 手机号输入自动格式化显示
- 利用已有的 `/region` 接口获取省市数据

## 4. 项目范围

### 4.1 范围包含
- 前端 `user/center.vue` 地址表单优化
- 省市区三级联动组件开发
- 手机号自动格式化/回显
- 调用已有 Region API

### 4.2 范围不包含
- 后端接口改动（已有接口可用）
- 数据库改动

## 5. 关键发现

### 5.1 已有资源
- 后端 Region 接口：
  - GET `/region/provinces` - 获取所有省份
  - GET `/region/cities/{provinceCode}` - 根据省份获取城市
  - GET `/region/districts/{cityCode}` - 根据城市获取区县
- 数据库已有完整省市区三级数据（region.sql）

### 5.2 当前问题
- 省市区使用普通文本输入框，无级联选择
- 手机号无格式化显示
- 前后端字段命名不一致，需做转换

### 5.3 前后端字段映射
| 前端字段 | 后端字段 |
|----------|----------|
| receiverName | rcvrName |
| receiverPhone | rcvrTel |
| province | prvcCde |
| city | cityCde |
| district | dstrctCde |
| detailAddress | dtlAddr |
| isDefault (0/1) | dftIndc (Y/N) |

## 6. 约束条件
- 不改动后端接口
- 不改动数据库结构
- 保持现有地址列表功能不变

## 7. 风险
| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|----------|
| 省市数据加载慢 | 低 | 中 | 缓存省市数据 |
| 字段映射不匹配 | 中 | 高 | 做好前后端字段转换 |
