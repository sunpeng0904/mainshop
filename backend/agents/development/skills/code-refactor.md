## Overview

识别代码坏味道，设计并执行重构方案，在保持功能不变的前提下优化代码结构和质量。

## When to Use

- 方法超过50行或参数超过5个需要拆分
- 发现重复代码需要提取公共方法
- 类过大（>500行）或职责过多需要拆分
- 存在过度耦合、违反SOLID原则等设计问题
- 重构后需要验证功能不变

## Core Pattern

| 重构类型 | 手法 | 效果 |
|----------|------|------|
| 方法重构 | 提取方法、方法重命名、参数对象 | 方法职责单一 |
| 类重构 | 提取类、提取接口、移动方法 | 类职责单一 |
| 代码清理 | 删除死代码、简化条件、消除重复 | 降低复杂度 |

## Implementation

1. **代码分析** - 识别代码坏味道（方法过长/参数过多/职责不单一/重复代码/过度耦合），分析代码结构，确定重构范围
2. **重构设计** - 设计重构方案，评估重构风险，制定重构计划
3. **重构执行** - 执行重构操作（提取方法/类/接口），保持功能不变
4. **验证测试** - 执行单元测试验证功能正确，生成重构报告

## Quick Reference

| 指标 | 阈值 |
|------|------|
| 方法长度 | <=50行 |
| 方法参数 | <=5个 |
| 类长度 | <=500行 |
| 圈复杂度 | <=10 |
| 重复代码 | <=5% |

## Quality Checklist

- [ ] 重构目标明确（解决什么问题）
- [ ] 重构方案合理（选择合适的手法）
- [ ] 功能保持不变（测试全部通过）
- [ ] 重构报告包含前后对比和收益

## Common Mistakes

- 重构和功能修改混在一起（应分开提交）
- 未在重构前确保测试覆盖导致无法验证
- 过度抽象引入不必要的复杂度
- 只重构局部忽略整体架构问题
