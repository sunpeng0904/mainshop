## Overview

确保所有代码符合中证开发规范，覆盖命名、风格、注释、质量、安全、异常处理和日志七大检查维度。

## When to Use

- 代码提交前需要进行规范合规检查
- 需要生成中证开发规范合规报告
- 代码评审中需要检查命名、风格、注释等规范
- 需要识别SQL注入、XSS等安全问题

## Core Pattern

| 检查维度 | 检查要点 | 合规标准 |
|----------|----------|----------|
| 命名规范 | 大驼峰类名、小驼峰方法名、全大写常量 | 100%合规 |
| 代码风格 | 4空格缩进、120字符行宽、K&R大括号 | 100%合规 |
| 注释规范 | 类/方法/字段注释完整 | public方法100%覆盖 |
| 代码质量 | 方法≤50行、类≤500行、圈复杂度≤10 | 达标率≥90% |
| 安全规范 | 参数化查询、输出编码、敏感信息加密 | 零高危 |

## Implementation

1. **规范检查** - 检查命名规范（类/方法/常量/变量/包名）、代码风格（缩进/行宽/空行/大括号）、注释规范（类/方法/字段/关键逻辑）
2. **代码质量检查** - 检查方法长度、类长度、圈复杂度、重复代码比例
3. **安全检查** - SQL注入（参数化查询）、XSS防护（输出编码）、敏感信息（加密存储）
4. **合规报告** - 按维度统计通过率，列出问题清单并提供修复建议

## Quick Reference

| 检查项 | 要求 |
|--------|------|
| 方法长度 | 不超过50行 |
| 类长度 | 不超过500行 |
| 圈复杂度 | 不超过10 |
| 重复代码 | 不超过5% |
| 行宽 | 不超过120字符 |
| 缩进 | 4个空格 |

## Quality Checklist

- [ ] 检查项覆盖七大维度
- [ ] 问题识别准确，定位到文件和行号
- [ ] 修复建议具体可行
- [ ] 合规报告包含通过率和问题清单

## Common Mistakes

- 日志中记录敏感信息（密码、token、身份证号）
- 吞掉异常不记录日志
- 使用字符串拼接SQL而非参数化查询
- 注释与代码不同步
