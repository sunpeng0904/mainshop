## Overview

系统性审查代码质量，覆盖风格、注释、业务逻辑、安全性、性能、可维护性六大维度，输出评审报告和改进建议。

## When to Use

- 代码提交前需要进行质量评审
- Pull Request需要代码审查
- 需要检查业务逻辑正确性和边界处理
- 需要评估代码安全性和性能

## Core Pattern

| 审查维度 | 重点检查项 |
|----------|-----------|
| 代码风格 | 命名规范、缩进格式、空行使用 |
| 注释质量 | 类/方法注释完整、关键逻辑有注释 |
| 代码质量 | 方法长度、类长度、圈复杂度、重复代码 |
| 业务逻辑 | 逻辑正确、边界处理、异常处理、并发安全 |
| 安全性 | 输入校验、SQL注入防护、XSS防护 |
| 性能 | 算法效率、数据库查询、缓存使用、资源释放 |

## Implementation

1. **代码审查** - 检查代码风格、命名规范、注释完整性
2. **逻辑审查** - 审查业务逻辑正确性、异常处理、边界条件
3. **安全审查** - 检查输入校验、SQL注入防护、XSS防护
4. **性能审查** - 评估算法复杂度、数据库查询效率、资源使用
5. **输出报告** - 按维度统计通过率，列出问题清单和改进建议

## Quick Reference

| 检查项 | 标准 |
|--------|------|
| 方法长度 | ≤50行 |
| 类长度 | ≤500行 |
| 圈复杂度 | ≤10 |
| 重复代码 | ≤5% |
| 行宽 | ≤120字符 |

## Quality Checklist

- [ ] 检查项覆盖六大维度
- [ ] 问题定位到文件和行号
- [ ] 严重程度分级（高/中/低）
- [ ] 改进建议具体可操作
- [ ] 评审结论明确（通过/有条件通过/不通过）

## Common Mistakes

- 只关注代码风格忽略业务逻辑
- 发现问题但不给出修复建议
- 未检查并发安全（如非线程安全的SimpleDateFormat）
- 未检查资源释放（如未关闭的流/连接）
- 忽略边界条件（null/空集合/最大值）
