# 架构设计

## Overview

设计系统整体架构，确保系统可扩展、可维护、高性能。涵盖技术架构、业务架构、数据架构三个维度。

## When to Use

- 需要设计系统整体架构
- 需要选择架构风格（单体/微服务/SOA）
- 需要设计分层结构
- 需要进行架构可行性评估
- 需要输出架构设计文档、架构图、部署图

## Core Pattern

| 维度 | 说明 | 输出 |
|------|------|------|
| 技术架构 | 技术栈选择、组件设计 | 技术架构图 |
| 业务架构 | 业务模块划分、核心流程 | 业务架构图 |
| 数据架构 | 数据模型、数据流向 | 数据架构图 |
| 部署架构 | 部署拓扑、环境规划 | 部署图 |

## Implementation

1. **需求分析** - 分析功能需求、非功能需求，识别架构需求
2. **架构选型** - 选择架构风格，确定架构模式，设计分层结构
3. **详细设计** - 设计技术架构、业务架构、数据架构
4. **架构评审** - 架构可行性评估、风险评估、优化建议

## Quality Checklist

- [ ] 架构风格选择合理
- [ ] 分层设计清晰
- [ ] 技术栈选择适当
- [ ] 满足非功能需求
- [ ] 架构图清晰易懂

## Common Mistakes

- 架构风格选择不合理，未考虑项目规模和团队能力
- 分层设计不清晰，层之间职责混乱
- 忽视非功能需求（性能、可用性、安全性）
- 架构图过于复杂，缺少清晰的层次关系
- 未进行架构评审就直接实施

## Quick Reference

| 架构风格 | 适用场景 | 特点 |
|----------|----------|------|
| 单体架构 | 小型项目 | 简单、快速开发 |
| 微服务架构 | 大型项目 | 独立部署、灵活扩展 |
| SOA架构 | 企业级应用 | 服务复用、松耦合 |
