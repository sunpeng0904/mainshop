# 技术选型

## Overview

基于需求和约束，选择最合适的技术栈。通过系统化的评估流程，确保技术选型决策有据可依。

## When to Use

- 需要选择前端/后端/数据库技术栈
- 需要对比多个技术方案
- 需要评估技术风险
- 需要输出技术选型报告

## Core Pattern

| 步骤 | 说明 | 输出 |
|------|------|------|
| 需求分析 | 识别技术需求和约束 | 评估标准 |
| 候选筛选 | 列出候选技术并初步筛选 | 候选列表 |
| 技术评估 | 多维度评估候选技术 | 对比分析 |
| 选型决策 | 综合评分并做出决策 | 选型报告 |

## Implementation

1. **需求分析** - 分析技术需求、识别技术约束、确定评估标准
2. **候选技术** - 列出候选技术、收集技术资料、初步筛选
3. **技术评估** - 功能完整性、性能、社区活跃度、学习成本、维护成本评估
4. **选型决策** - 综合评分、风险评估、最终决策

### 2.2 后端技术

### 4.2 备选方案

## Quality Checklist

- [ ] 评估标准合理
- [ ] 候选技术全面
- [ ] 对比分析客观
- [ ] 选型决策有据
- [ ] 风险评估充分

## Common Mistakes

- 只凭个人偏好选择技术，缺乏客观评估
- 忽视团队学习成本和维护成本
- 未考虑社区活跃度和长期支持
- 候选技术范围过窄，缺少对比
- 风险评估不充分，缺少应对措施

## Quick Reference

| 评估维度 | 关键指标 |
|----------|----------|
| 功能完整性 | 是否满足核心需求 |
| 性能 | 响应时间、吞吐量 |
| 社区活跃度 | GitHub stars、更新频率 |
| 学习成本 | 文档质量、学习曲线 |
| 维护成本 | 长期支持、升级难度 |
