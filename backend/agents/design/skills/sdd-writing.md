## Overview

按照阿里SDD规范编写软件设计说明书，覆盖概要设计(HLD)、详细设计(LLD)、数据库设计(DBD)和接口设计(IFD)四个层级。遵循需求阶段定义的SDD规范约束，确保设计文档结构规范、内容完整、可追溯。

## When to Use

- 需求阶段已输出SDD规范约束，需要开始编写设计文档
- 需要编写概要设计说明书(HLD)
- 需要编写详细设计说明书(LLD)
- 需要编写数据库设计说明书(DBD)
- 需要编写接口设计说明书(IFD)

**Do NOT use when:**
- 需求尚未完成，SRS文档未产出
- SDD规范约束未定义
- 仅需进行技术选型而非完整设计

## Core Pattern

| 层级 | 文档 | 核心内容 | 输入 |
|------|------|----------|------|
| L1 | HLD | 架构设计、模块划分、接口概览 | SRS、SDD规范约束 |
| L2 | LLD | 类设计、序列图、算法设计、异常处理 | HLD |
| L3 | DBD | 表结构、索引、存储过程、数据迁移 | HLD、数据模型 |
| L4 | IFD | API定义、报文格式、错误码 | HLD、接口概览 |

## Implementation

### Step 1: 编写概要设计说明书(HLD)

HLD是SDD的核心文档，描述系统级架构设计。

**编写要点：**

**1.1 引言**
- 编写目的：说明本文档的编写意图和预期读者
- 读者对象：列出本文档的目标读者（架构师、开发人员、测试人员等）
- 术语与缩略语：引用SRS术语表，补充设计阶段新增术语
- 参考文档：列出SRS、SDD规范约束等参考文档

**1.2 系统概述**
- 系统目标：引用SRS中的业务目标和技术目标
- 系统约束：技术约束、业务约束、资源约束
- 设计原则：高内聚低耦合、单一职责、开闭原则等

**1.3 架构设计**
- 架构风格选型：说明选择的架构风格（单体/微服务/SOA）及理由
- 系统上下文图：描述系统与外部系统的交互关系
- 分层架构设计：明确各层职责和边界
- 模块划分：将系统划分为逻辑模块，定义模块职责
- 部署架构：描述部署拓扑和环境规划

**1.4 模块设计**
- 对每个模块描述：模块职责、对外接口、依赖关系
- 每个模块必须映射到SRS中的功能模块

**1.5 数据设计**
- 数据模型概览：核心实体和关系
- 数据流设计：数据在系统中的流转路径

**1.6 接口设计**
- 外部接口：系统对外提供的接口概览
- 内部接口：模块间的接口定义
- 第三方接口：依赖的外部系统接口

**1.7 非功能设计**
- 安全设计：认证、授权、加密方案
- 性能设计：缓存、并发、数据库优化方案
- 高可用设计：容灾、故障转移、降级方案

### Step 2: 编写详细设计说明书(LLD)

LLD描述模块级的详细设计方案。

**编写要点：**

**2.1 类设计**
- 类图：展示核心类及其关系
- 类职责说明：每个类的职责和关键方法
- 设计模式应用：使用的GoF设计模式

**2.2 序列图**
- 核心业务流程的时序交互
- 标注关键的同步/异步调用

**2.3 状态图（选填）**
- 有状态实体的状态转换图
- 状态转换条件和触发事件

**2.4 算法设计（选填）**
- 复杂业务逻辑的算法描述
- 算法的时间/空间复杂度分析

**2.5 异常处理**
- 异常分类：系统异常、业务异常、第三方异常
- 异常处理策略：重试、降级、告警
- 错误码定义：错误码编码规则和清单

### Step 3: 编写数据库设计说明书(DBD)

DBD描述数据库的详细设计方案。

**编写要点：**

**3.1 表结构设计**
- 表清单：所有数据库表的列表
- 字段定义：字段名、类型、长度、约束、默认值、说明
- 主键/外键：主键策略、外键关系
- 审计字段：创建时间、修改时间、创建人、修改人

**3.2 索引设计**
- 索引清单：所有索引的列表
- 索引类型：主键索引、唯一索引、普通索引、组合索引
- 索引理由：说明每个索引的使用场景

**3.3 存储过程（选填）**
- 存储过程清单和用途说明

**3.4 数据迁移方案（选填）**
- 存量数据迁移策略
- 数据清洗规则
- 迁移验证方案

### Step 4: 编写接口设计说明书(IFD)

IFD描述API的详细定义。

**编写要点：**

**4.1 接口概述**
- 接口版本、基础路径、认证方式

**4.2 接口详细定义**
- URL路径和HTTP方法
- 请求参数（路径参数、查询参数、请求体）
- 响应格式（成功响应、错误响应）
- 错误码清单
- 业务规则说明

**4.3 接口依赖关系**
- 接口间的调用关系
- 接口与第三方系统的依赖

### Step 5: 建立追溯矩阵

将SDD各层级与SRS需求建立追溯关系。

```
SRS需求 → HLD模块 → LLD类/序列 → DBD表 → IFD接口
REQ-001 → §4.1用户模块 → §2.1用户类 → §3.1用户表 → §4.1用户接口
```

### Step 6: 质量自检

对照SDD规范约束进行质量自检。

1. **完整性自检**: SRS中100%的功能需求和非功能需求是否已覆盖
2. **一致性自检**: 设计方案与SRS描述是否一致
3. **可实现性自检**: 设计方案是否技术可行
4. **规范性自检**: 是否符合SDD结构规范
5. **追溯性自检**: 是否建立了完整的追溯映射

## Quality Checklist

- [ ] HLD覆盖SRS中100%的功能需求和非功能需求
- [ ] 每个模块有明确的职责说明和SRS映射
- [ ] 架构图清晰，分层职责明确
- [ ] LLD包含核心类设计和序列图
- [ ] DBD包含完整的表结构和索引设计
- [ ] IFD包含完整的请求/响应定义和错误码
- [ ] 追溯矩阵完整，每个设计元素可追溯到SRS
- [ ] 非功能设计覆盖安全、性能、高可用
- [ ] 风险与对策已识别和记录
- [ ] 文档版本管理规范

## Common Mistakes

| 错误 | 原因 | 修正方法 |
|------|------|----------|
| HLD与SRS脱节 | 设计时未参考SRS | 每个设计元素必须映射到SRS需求编号 |
| LLD缺少序列图 | 只写类图不写交互 | 核心业务流程必须有序列图描述 |
| DBD缺少索引设计 | 只建表不考虑索引 | 根据查询场景设计必要索引 |
| IFD错误码不规范 | 错误码编码随意 | 遵循错误码编码规则（BIZ-/SYS-/EXT-） |
| 非功能设计空泛 | 只写概念不写方案 | 每个非功能需求必须有具体实现方案 |
| 忽略异常处理 | 只写正常流程 | LLD必须包含异常分类和处理策略 |

## Dependencies

- **Before**: SRS文档已产出，SDD规范约束已定义
- **After**: 输出完整的SDD文档体系（HLD/LLD/DBD/IFD），供开发阶段使用
