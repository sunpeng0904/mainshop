# 权限设计

## Overview

设计完整的权限体系，确保系统安全可控。基于RBAC模型，实现功能权限、数据权限、菜单权限的精细化控制。

## When to Use

- 需要设计系统权限体系
- 需要设计角色权限分配
- 需要设计菜单权限结构
- 需要设计数据权限控制

## Core Pattern

| 权限类型 | 说明 | 控制粒度 |
|----------|------|----------|
| 功能权限 | 控制菜单和按钮访问 | 菜单级、按钮级 |
| 数据权限 | 控制数据访问范围 | 行级、列级 |
| 接口权限 | 控制API访问 | API级别 |

## Implementation

1. **需求分析** - 分析功能权限需求、识别用户角色、确定权限粒度
2. **权限模型设计** - 设计RBAC模型、权限粒度、数据权限
3. **角色设计** - 定义系统角色、分配角色权限、设计角色继承
4. **菜单设计** - 设计菜单结构、分配菜单权限、设计按钮权限

## Templates

### 权限设计文档模板

```markdown
# 权限设计文档

## 1. 权限模型
### 1.1 RBAC模型
- User → Role → Permission → Resource

### 1.2 权限粒度
- 功能权限：控制菜单和按钮访问
- 数据权限：控制数据访问范围
- 字段权限：控制字段可见性

## 2. 角色定义
| 角色编码 | 角色名称 | 角色描述 | 权限列表 |
|----------|----------|----------|----------|
| ADMIN | 系统管理员 | 系统管理 | 所有权限 |
| USER | 普通用户 | 基本操作 | 基本功能 |
| AUDITOR | 审计员 | 审计查看 | 查看权限 |

## 3. 权限定义
### 3.1 菜单权限
| 权限编码 | 权限名称 | 权限类型 | 父权限 |
|----------|----------|----------|--------|
| system | 系统管理 | 目录 | - |
| system:user | 用户管理 | 菜单 | system |
| system:user:add | 新增用户 | 按钮 | system:user |

### 3.2 数据权限
| 权限编码 | 权限名称 | 数据范围 |
|----------|----------|----------|
| data:own | 仅本人 | 本人数据 |
| data:dept | 本部门 | 本部门数据 |
| data:all | 全部 | 全部数据 |

## 4. 菜单结构
├── 首页
├── 系统管理
│   ├── 用户管理
│   ├── 角色管理
│   ├── 菜单管理
│   └── 字典管理
├── 业务管理
└── 个人中心

## 5. 权限分配矩阵
| 功能 | 管理员 | 普通用户 | 审计员 |
|------|--------|----------|--------|
| 用户管理 | ✓ | ✗ | ✗ |
| 角色管理 | ✓ | ✗ | ✗ |
| 数据查看 | ✓ | ✓ | ✓ |
| 数据导出 | ✓ | ✗ | ✓ |
```

## Quality Checklist

- [ ] 权限模型合理
- [ ] 角色定义完整
- [ ] 权限粒度适当
- [ ] 菜单结构清晰
- [ ] 符合最小权限原则

## Common Mistakes

- 权限粒度过粗，无法满足业务需求
- 缺少数据权限控制，数据泄露风险
- 角色定义不完整，权限分配不合理
- 菜单结构混乱，用户体验差
- 忽视最小权限原则，权限过度分配
