# 安全设计

## Overview

设计系统安全方案，确保系统安全可控。涵盖认证、授权、加密、审计四个安全维度。

## When to Use

- 需要设计系统安全方案
- 需要设计认证授权方案
- 需要设计数据加密方案
- 需要设计审计日志方案
- 需要进行安全风险评估

## Core Pattern

| 安全维度 | 说明 | 关键措施 |
|----------|------|----------|
| 认证 | 身份验证 | 账号密码、多因素认证 |
| 授权 | 访问控制 | RBAC、数据权限 |
| 加密 | 数据保护 | 传输加密、存储加密 |
| 审计 | 操作追溯 | 登录日志、操作日志 |

## Implementation

1. **需求分析** - 分析安全需求、识别安全风险、确定安全等级
2. **认证设计** - 设计认证方案、会话管理、多因素认证
3. **授权设计** - 设计授权模型、访问控制、权限管理
4. **加密设计** - 设计传输加密、存储加密、密钥管理
5. **审计设计** - 设计审计日志、监控告警、应急响应

## Templates

### 安全设计方案模板

```markdown
# 安全设计方案

## 1. 安全目标
| 目标 | 说明 |
|------|------|
| 机密性 | 保护数据不被未授权访问 |
| 完整性 | 保护数据不被篡改 |
| 可用性 | 保证系统可用 |
| 可追溯性 | 所有操作可追溯 |

## 2. 认证设计
### 2.1 认证方式
| 方式 | 适用场景 | 说明 |
|------|----------|------|
| 账号密码 | 普通登录 | 基础认证 |
| 手机验证码 | 快捷登录 | 辅助认证 |
| OAuth2.0 | 第三方登录 | 外部认证 |
| 多因素认证 | 敏感操作 | 增强认证 |

### 2.2 会话管理
- 会话超时：30分钟
- 单点登录：支持
- 并发控制：单用户单会话

## 3. 授权设计
### 3.1 访问控制
- 基于角色的访问控制（RBAC）
- 基于属性的访问控制（ABAC）
- 数据级权限控制

### 3.2 权限粒度
- 功能权限：菜单、按钮
- 数据权限：行级、列级
- 接口权限：API级别

## 4. 加密设计
### 4.1 传输加密
- HTTPS强制使用
- TLS 1.2+
- 证书管理

### 4.2 存储加密
| 数据类型 | 加密方式 | 说明 |
|----------|----------|------|
| 密码 | BCrypt | 单向加密 |
| 敏感信息 | AES | 对称加密 |
| 密钥 | RSA | 非对称加密 |

## 5. 安全防护
### 5.1 输入校验
- SQL注入防护
- XSS防护
- CSRF防护

### 5.2 接口安全
- 接口签名
- 防重放攻击
- 防篡改

### 5.3 数据安全
- 数据脱敏
- 数据备份
- 数据销毁

## 6. 审计设计
### 6.1 审计日志
| 日志类型 | 记录内容 | 保留时间 |
|----------|----------|----------|
| 登录日志 | 登录时间、IP、结果 | 1年 |
| 操作日志 | 操作内容、操作人 | 3年 |
| 安全日志 | 安全事件 | 5年 |

### 6.2 监控告警
- 异常登录告警
- 敏感操作告警
- 系统异常告警

## 7. 应急响应
- 安全事件分级
- 应急响应流程
- 恢复方案
```

## Quality Checklist

- [ ] 安全目标明确
- [ ] 认证方案完善
- [ ] 授权粒度适当
- [ ] 加密方案有效
- [ ] 审计机制健全

## Common Mistakes

- 安全目标不明确，缺乏系统性安全设计
- 认证方式单一，缺少多因素认证
- 授权粒度过粗，无法满足业务需求
- 忽视传输加密，数据在传输中被窃取
- 审计日志不完整，无法追溯安全事件
