# 性能设计

## Overview

设计系统性能方案，确保系统满足性能需求。涵盖缓存设计、并发设计、数据库优化、性能测试。

## When to Use

- 需要设计系统性能方案
- 需要设计缓存策略
- 需要设计并发处理方案
- 需要设计数据库优化方案
- 需要进行性能测试

## Core Pattern

| 优化维度 | 说明 | 关键指标 |
|----------|------|----------|
| 缓存设计 | 多级缓存策略 | 命中率、响应时间 |
| 并发设计 | 限流、熔断、降级 | TPS、并发数 |
| 数据库优化 | 索引、分库分表、读写分离 | 查询时间、吞吐量 |
| 性能测试 | 压力、负载、容量测试 | 响应时间、可用性 |

## Implementation

1. **需求分析** - 分析性能指标、识别性能瓶颈、确定优化目标
2. **缓存设计** - 设计缓存策略、选择缓存技术、设计缓存更新机制
3. **并发设计** - 设计并发处理方案、限流策略、熔断降级
4. **数据库优化** - 设计索引策略、分库分表、读写分离

## Templates

### 性能设计方案模板

```markdown
# 性能设计方案

## 1. 性能目标
| 指标 | 目标值 | 说明 |
|------|--------|------|
| 响应时间 | <200ms | 接口平均响应时间 |
| 并发数 | 1000 | 系统支持并发用户数 |
| TPS | 500 | 每秒事务处理量 |
| 可用性 | 99.9% | 系统可用性 |

## 2. 缓存设计
### 2.1 缓存策略
| 数据类型 | 缓存策略 | 过期时间 | 更新机制 |
|----------|----------|----------|----------|
| 用户信息 | 读写穿透 | 30分钟 | 主动更新 |
| 字典数据 | 只读缓存 | 24小时 | 定时刷新 |
| 热点数据 | 本地缓存 | 5分钟 | LRU淘汰 |

### 2.2 缓存架构
- 应用 → 本地缓存 → Redis集群 → 数据库

## 3. 并发设计
### 3.1 限流策略
| 接口 | 限流方式 | 限流值 | 说明 |
|------|----------|--------|------|
| 登录接口 | 令牌桶 | 100/s | 防止暴力登录 |
| 查询接口 | 滑动窗口 | 1000/s | 防止恶意请求 |

### 3.2 熔断降级
| 服务 | 熔断阈值 | 降级策略 | 说明 |
|------|----------|----------|------|
| 支付服务 | 50%失败率 | 返回默认值 | 保证核心流程 |
| 推送服务 | 30%失败率 | 异步重试 | 非核心功能 |

## 4. 数据库优化
### 4.1 索引策略
| 表名 | 索引字段 | 索引类型 | 说明 |
|------|----------|----------|------|
| t_user | user_code | 唯一索引 | 用户编码查询 |
| t_order | order_time | 普通索引 | 订单时间查询 |

### 4.2 分库分表
| 表名 | 分片键 | 分片策略 | 说明 |
|------|--------|----------|------|
| t_order | user_id | 用户维度 | 按用户分片 |
| t_log | create_time | 时间维度 | 按月分表 |

## 5. 性能测试计划
| 测试类型 | 测试目标 | 测试工具 | 说明 |
|----------|----------|----------|------|
| 压力测试 | 验证TPS | JMeter | 模拟高并发 |
| 负载测试 | 验证稳定性 | JMeter | 持续负载 |
| 容量测试 | 验证数据量 | 自研工具 | 大数据量 |
```

## Quality Checklist

- [ ] 性能目标明确
- [ ] 缓存策略合理
- [ ] 并发方案可行
- [ ] 数据库优化有效
- [ ] 测试计划完整

## Common Mistakes

- 性能目标不量化，无法验证优化效果
- 缓存策略不当，缓存穿透或雪崩
- 忽视并发问题，缺少限流和熔断
- 数据库索引设计不合理，查询性能差
- 缺少性能测试，无法验证优化效果
