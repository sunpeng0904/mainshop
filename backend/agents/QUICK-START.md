# AI 脚手架 - 快速入门指南

## 一、脚手架使用方式

本脚手架是一个 **AI Agent 协作体系**，通过与 AI 对话来驱动项目开发全流程。

### 使用方式
1. **直接对话**：在 OpenClaw 中与 AI 对话，按阶段调用各个 Agent
2. **参考模板**：使用各个 Skill 文档作为提示词模板
3. **遵循流程**：按照 WORKFLOW.md 中的审核流程推进

---

## 二、快速开始（3步走）

### 第1步：项目初始化

**对话示例**：
```
我想启动一个新项目，项目名称是"用户管理系统"，请帮我：
1. 初始化项目，生成项目章程
2. 收集需求，生成需求池
3. 分析需求，确定优先级
```

**AI 会调用**：
- 项目管理 Agent → `project-init` Skill
- 需求 Agent → `requirement-gather` Skill
- 需求 Agent → `requirement-analysis` Skill

**产出物**：
- 项目章程
- 需求池
- 需求分析报告

### 第2步：设计与开发

**对话示例**：
```
基于需求文档，请帮我：
1. 设计系统架构
2. 制定词根命名规范
3. 设计API接口
4. 生成代码框架
```

**AI 会调用**：
- 设计 Agent → `architecture-design` Skill
- 设计 Agent → `root-standard` Skill
- 设计 Agent → `api-design` Skill
- 开发 Agent → `code-generate` Skill

**产出物**：
- 架构设计文档
- 词根字典
- API设计文档
- 源代码

### 第3步：测试与部署

**对话示例**：
```
代码开发完成，请帮我：
1. 生成单元测试
2. 制定测试计划
3. 制定部署方案
4. 执行部署
```

**AI 会调用**：
- 开发 Agent → `unit-test` Skill
- 测试 Agent → `test-plan` Skill
- 部署 Agent → `deploy-plan` Skill
- 部署 Agent → `deploy-execute` Skill

**产出物**：
- 单元测试
- 测试计划
- 部署方案
- 部署记录

## 三、完整对话示例

### 场景：从零开始创建用户管理系统

**第1轮对话 - 项目启动**
```
用户：我想启动一个用户管理系统项目，请帮我初始化项目

AI：好的，我来帮你初始化项目。请提供以下信息：
1. 项目背景是什么？
2. 业务目标是什么？
3. 主要干系人有哪些？
4. 有什么约束条件？

用户：统一管理公司用户账号，干系人有张三（产品）、李四（技术），4周内上线，用Java

AI：收到，正在生成项目章程...
[输出项目章程]

请确认项目章程内容，确认后我将继续进行需求收集。
```

**第2轮对话 - 需求收集**
```
用户：项目章程确认，请继续收集需求

AI：好的，我来收集需求。请确认以下功能需求：
1. 用户注册、登录、注销
2. 用户信息管理（CRUD）
3. 角色管理
4. 权限管理
5. 操作日志
6. 单点登录（SSO）

是否还有其他需求？

用户：暂时没有了

AI：收到，正在生成需求池和需求分析报告...
[输出需求池和分析报告]

需求优先级：
- P0：用户登录、用户管理、角色管理、权限管理
- P1：单点登录、操作日志
- P2：用户注册（可后续迭代）

请确认需求分析结果。
```

**第3轮对话 - 系统设计**
```
用户：需求确认，请进行系统设计

AI：好的，我来进行系统设计。请确认以下技术选型：
- 前端：Vue.js 3 + Element Plus
- 后端：Spring Boot 3 + MyBatis Plus
- 数据库：MySQL 8.0
- 缓存：Redis 6.x
- 认证：JWT

用户：确认

AI：收到，正在生成架构设计、词根字典、API设计...
[输出架构设计、词根字典、API设计]

设计要点：
1. 分层架构：Controller → Service → Manager → DAO
2. 统一词根：用户(user)、角色(role)、权限(permission)
3. RESTful API：/api/v1/users, /api/v1/roles

请确认设计文档。
```

**第4轮对话 - 代码生成**
```
用户：设计确认，请生成代码

AI：收到，正在生成代码框架...
[输出实体类、Service、Controller代码]

代码结构：
src/main/java/com/example/ums/
├── controller/UserController.java
├── service/UserService.java
├── service/impl/UserServiceImpl.java
├── entity/User.java
├── dto/UserCreateDTO.java
└── vo/UserVO.java

代码符合中证开发规范：
✅ 命名规范
✅ 注释完整
✅ 分层清晰
✅ 异常处理

请确认代码。
```

**第5轮对话 - 测试部署**
```
用户：代码确认，请制定测试和部署方案

AI：收到，正在生成测试计划和部署方案...
[输出测试计划、部署方案]

测试计划：
- 功能测试：10个用例
- 接口测试：20个用例
- 性能测试：1000并发

部署方案：
- 环境：Docker容器化
- 步骤：构建镜像 → 推送仓库 → 部署服务
- 回滚：保留3个历史版本

请确认测试和部署方案。
```

## 四、审核流程示例

每个阶段完成后，需要经过审核：

```
AI：项目章程已生成，请确认是否通过审核？

审核清单：
✅ 项目目标明确
✅ 范围定义清晰
✅ 干系人识别完整
✅ 里程碑合理
✅ 风险已识别

审核Agent评分：92/100

请确认：
1. 通过 - 进入下一阶段
2. 驳回 - 需要修改后重新提交
3. 有条件通过 - 需要补充某些内容

用户：通过

AI：收到，项目章程审核通过，进入需求收集阶段。
```

## 五、关键提示

### 1. 不要跳过审核
每个阶段必须经过审核才能进入下一阶段，确保质量。

### 2. 使用词根字典
所有命名必须使用词根字典中的标准术语，保持一致性。

### 3. 符合中证规范
设计和开发阶段必须符合中证体系要求。

### 4. 人工确认优先
无论审核Agent评分多少，最终都需要人工确认。

### 5. 可追溯性
所有产出物均可追溯到源头需求。

## 六、常见问题

### Q1：如何开始一个新项目？
A：直接告诉AI你想启动什么项目，AI会引导你完成初始化。

### Q2：如何查看某个阶段的产出物？
A：告诉AI你想查看哪个阶段的产出物，AI会为你生成。

### Q3：如何修改已确认的产出物？
A：告诉AI你想修改什么，AI会帮你更新并重新提交审核。

### Q4：审核不通过怎么办？
A：根据审核反馈修改后重新提交，AI会再次审核。

### Q5：如何跳过某个阶段？
A：不可以跳过，必须按照流程顺序推进。
