# 审核工作流说明

## 流程总览

每个阶段必须经过 **三步审核** 才能进入下一阶段：

```
生成 Agent 产出 → 审核 Agent 评分 → 人工审核确认 → 进入下一阶段
```

## 审核流程详解

### 第一步：生成 Agent 产出

每个阶段的生成 Agent 负责该阶段的具体工作产出：
- 项目管理 Agent → 项目计划、进度报告等
- 需求 Agent → 需求文档、用例等
- 设计 Agent → 架构设计、API 设计等
- 开发 Agent → 代码、单元测试等
- 测试 Agent → 测试计划、测试报告等
- 部署 Agent → 部署方案、上线检查等

### 第二步：审核 Agent 评分

每个阶段配备专属审核 Agent，负责：
1. **完整性检查** - 产出物是否完整
2. **规范性检查** - 是否符合中证标准
3. **质量评分** - 按照评分标准打分（0-100分）
4. **问题清单** - 列出发现的问题和改进建议
5. **生成审核报告** - 输出标准化审核报告

**评分标准：**
- 90-100分：优秀，可直接提交人工审核
- 70-89分：良好，建议修改后提交
- 60-69分：及格，需要修改后重新审核
- 0-59分：不合格，需要重新生成

### 第三步：人工审核确认

**无论审核 Agent 给出什么分数，都必须经过人工审核。**

人工审核内容：
1. 审核 Agent 的评分是否合理
2. 产出物是否满足业务需求
3. 是否有遗漏的关键点
4. 最终决定：通过 / 驳回 / 有条件通过

### 第四步：流转到下一阶段

人工审核通过后：
1. 标记当前阶段为"已完成"
2. 将产出物传递给下一阶段
3. 下一阶段 Agent 开始工作

## 审核报告模板

每份审核报告必须包含以下内容：

```markdown
# 审核报告

## 基本信息
- 审核阶段：[阶段名称]
- 审核时间：[YYYY-MM-DD HH:mm]
- 审核人：[Agent名称]
- 产出物：[文件列表]

## 评分结果
- 完整性得分：XX/25
- 规范性得分：XX/25
- 质量得分：XX/25
- 可维护性得分：XX/25
- **总分：XX/100**

## 发现问题
1. [问题描述] - [严重程度：高/中/低]
2. ...

## 改进建议
1. [建议内容]
2. ...

## 审核结论
- [ ] 通过
- [ ] 驳回
- [ ] 有条件通过（条件：...）

## 人工审核
- 审核人：_________
- 审核时间：_________
- 审核结果：通过 / 驳回 / 有条件通过
- 备注：_________
```

## 状态流转

```
[待开始] → [进行中] → [待审核] → [审核中] → [待人工确认] → [已完成]
                                    ↓
                              [已驳回] → [进行中]（重新生成）
```

## 关键规则

1. **不可跳过** - 任何阶段都不能跳过审核流程
2. **不可逆向** - 已完成的阶段不能回退（只能通过变更流程）
3. **人工优先** - 人工审核是最终决定，审核 Agent 评分仅作参考
4. **全程记录** - 所有审核记录必须保存，用于追溯
5. **超时处理** - 人工审核超过 24h 未响应，自动提醒
6. **驳回重审** - 驳回或有条件通过后，修改完成必须重新进行审核，不可直接进入下一阶段
7. **产物保留** - 项目只要存在新增需求或修改需求，整个项目周期必须默认保留产物，在 `docs/<需求目录名>/` 下按阶段编号存储

## 产物保留规范

每个需求/变更必须在 `docs/` 下创建独立目录，保留完整生命周期产物：

```
docs/<需求目录名>/
├── 01-project-charter.md        # 项目章程
├── 02-requirement-spec.md       # 需求规格说明书
├── 02-requirement-review.md     # 需求审核报告
├── 03-design-spec.md            # 设计文档
├── 03-design-review.md          # 设计审核报告
├── 04-development-review.md     # 开发审核报告
├── 05-test-report.md            # 测试报告
├── 06-deployment-report.md      # 部署报告
└── 07-project-completion.md     # 项目总结报告
```

**规则：**
- 目录名使用 kebab-case，与 `openspec/changes/` 中的变更名保持一致
- 每个阶段完成后，必须将产物写入对应编号的文件
- 产物内容必须包含审核评分和审核结论
- 目录结构根据实际情况按需新增，不强制要求一次性创建所有文件
