## 需求检查点

| 序号 | 检查点 | 内容 |
| --- | --- | --- |
| 1 | 业务场景 | 明确用户范围以及用户权限（菜单权限、按钮权限、数据权限） |
| 2 | 业务场景 | 明确整体业务流程 |
| 3 | 业务场景 | 明确系统间业务场景控制 |
| 4 | 结构化数据 | 明确数据来源 |
| 5 | 结构化数据 | 明确有几个表单数据 |
| 6 | 结构化数据 | 明确每个表单定义的业务唯一性 |
| 7 | 结构化数据 | 明确每个表单的最大条数限制 |
| 8 | 结构化数据 | 明确表单排序规则（列表） |
| 9 | 结构化数据 | 明确表单每页几条（列表） |
| 10 | 结构化数据字段 | 唯一性 |
| 11 | 结构化数据字段 | 数据类型 |
| 12 | 结构化数据字段 | 生成规则 |
| 13 | 结构化数据字段 | 校验规则 |
| 14 | 结构化数据字段 | 是否必填 |
| 15 | 结构化数据字段 | 长度 |
| 16 | 结构化数据字段 | 精度 |
| 17 | 结构化数据字段 | 默认值 |
| 18 | 结构化数据字段 | 是否数据字典 |
| 19 | 结构化数据字段 | 数据字典明细（是数据字典） |
| 20 | 非结构化数据 | 明确附件类型 |
| 21 | 非结构化数据 | 明确单一附件最大大小 |
| 22 | 非结构化数据 | 明确附件最大数量 |
| 23 | 共性检查 | 修改、保存、提交、删除二次确认弹窗控制以及描述 |
| 24 | 共性检查 | 校验规则校验住时的弹窗描述 |

## 公司CMMI需求检查点

| 序号 | 检查点 | 内容 | 是否完备 | 是否检查 |
| --- | --- | --- | --- | --- |
| 1 | 需求背景 | 包含需求提出单位、遇到的问题。 |  |  |
| 2 | 管理目标 | 系统建设后期望达到的目标和业务价值是否有明确且有测量标准。 |  |  |
| 3 | 用户范围 | 会内部门、派出机构、交易所等。例：上市部一处到六处用户、各地证监局、沪深交易所等。 |  | 是 |
| 4 | 用户权限 | 是否清晰界定了系统用户角色及其功能和数据权限 |  | 是 |
| 5 | 使用频次 | 是否清晰定义了不同角色人员使用频次及使用高峰时段。例：业务人员，平均每月10次，月末最后一周为高峰期。 |  | 是 |
| 6 | 优先级/紧急度 | 每个需求是否明确定义了优先级、紧急度。 |  |  |
| 7 | 业务规则 | 业务规则本身是否清晰，逻辑是否自洽，是否提供了与规则相符的样例数据及计算过程样例。 |  | 是 |
| 8 | 业务主流程及分支流程 | 主流程及分支流程是否衔接顺畅合理，各流程节点的参与角色、职责、操作权限是否明确，节点流转的条件及方式是否明确，节点回退的条件及方式是否明确。是否已经提供了对应的流程图（一般超过3个节点就应该提供流程图）。 |  | 是 |
| 9 | 异常场景 | 是否明确定义了所有的异常场景及其出现条件和处理方式。 |  | 是 |
| 10 | 输入项 | 每个表单的输入项是否明确定义了字段唯一性、类型、输入或生成规则、是否必填、长度和精度要求、默认值等。 |  | 是 |
| 11 | 输出项 | 是否明确定义了输出页的信息项、分页要求、默认数据展示规则（排序要求、字段过长展现形式，无数据或过少时的展现形式）。 |  | 是 |
| 12 | 配套改造 | 是否明确涉及哪些相关系统的配套改造及其调用方式（API/消息/数据库直连）、时效性（实时/定时及其间隔）、身份认证与待办集成要求。相关系统负责人是否提供可行性答复及工作量评估。 |  |  |
| 13 | 数据 | 数据采集统计等口径是否清晰，数据校验规则是否明确，数据修订规则是否明确,与现行的数据标准和元数据管理制度是否一致。是否涉及内外网交换，是否明确数据同步的时间要求。是否有历史数据的迁移，铺底数据的构造，历史或者铺底数据的来源，是历史系统中数据迁移过来还是历史存档文件中获取。明确定义数据提取后进入非生产系统时数据脱敏的范围及规则。 |  |  |
| 14 | 报表需求 | 与业务相关的原始报表是否提供。报表的字段、统计维度、计算规则、实时/T+1、查看权限是否有明确定义。 |  | 是 |
| 15 | 移动化需求 | 是否明确用户提出的移动化需求符合会内密级要求；是否已经和测试部确认证联讯端的移动化需求。 |  |  |
| 16 | 界面原型 | 是否满足公司规范；是否按角色、按状态给出原型界面。如：填报人、审批人；浏览态、编辑态、审核态。页面上下文的过渡方式是否明确。如：新开页签、弹出窗口、内部嵌套。 |  | 是 |
| 17 | 非功能需求-审计日志要求 | 审计日志构成是否有明确要求。包含以下哪些内容：登录日志、数据的创建人\修改人及时间、业务数据发生变化前后内容 |  | 是 |
| 18 | 非功能需求-网络访问要求 | 系统使用的网络限制与要求，是否区分外网、证联网、内网、涉密内网 |  | 是 |
| 19 | 非功能需求-浏览器兼容性要求 | 要求支持的浏览器及其版本是否明确？必须优先保证会内国产机器的奇安信浏览器 |  | 是 |
| 20 | 非功能需求-可用性要求 | RTO和RPO时长要求是否明确。 |  |  |
| 21 | 非功能需求-存储要求 | 数据库数据保存多少时间？总计XX万条，总计XXGB。业务文件保存多少时间？总计XX万个，总计XXGB。日志文件保存多少时间？，总计XXGB。 |  |  |
| 22 | 非功能需求-性能要求 | 例100万条数据，30并发，每接口响应时长<2秒，每页面响应时长<3秒。 |  |  |
| 23 | 安全需求 | 是否明确定义了网络（访问控制）、身份鉴别、数据存储的安全性要求及是否明确定义了数据备份策略 |  |  |
