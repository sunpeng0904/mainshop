## Overview

从各个渠道收集原始需求，通过多种方法（访谈、问卷、文档分析等）形成结构化的需求池。

## When to Use

- 项目启动阶段需要收集干系人需求
- 需要对业务部门、技术团队、终端用户开展访谈
- 存在已有文档需要分析提取需求
- 需要建立或维护需求池

## Core Pattern

| 场景 | 做法 |
|------|------|
| 一对一深度访谈 | 设计结构化问题，记录要点和后续行动 |
| 大范围调研 | 使用问卷覆盖更多干系人 |
| 已有文档分析 | 从项目章程、历史文档中提取需求 |
| 需求池维护 | 去重、分类、编号，保持需求可追溯 |

## Implementation

1. **需求来源识别** - 明确业务部门、技术团队、终端用户、管理层、外部监管等来源
2. **选择收集方法** - 根据场景选择访谈、问卷、文档分析、观察或头脑风暴
3. **需求记录** - 记录原始需求，分类整理，初步评估
4. **需求池维护** - 需求去重、分类、编号，确保每条需求可追溯

## Templates

### 需求池模板

```markdown
# 需求池

## 基本信息
- 项目名称：[名称]
- 收集日期：[YYYY-MM-DD]
- 收集人：[姓名]

## 需求清单

| 编号 | 需求描述 | 来源 | 类型 | 优先级 | 状态 |
|------|----------|------|------|--------|------|
| REQ-001 | [描述] | 业务部门 | 功能 | 高 | 待分析 |
| REQ-002 | [描述] | 用户 | 非功能 | 中 | 待分析 |

## 需求分类
### 功能需求
- [需求1]

### 非功能需求
- 性能需求、安全需求、可用性需求

### 约束条件
- 技术约束、业务约束
```

### 访谈记录模板

```markdown
# 访谈记录

## 基本信息
- 访谈对象：[姓名/职位]
- 访谈时间：[YYYY-MM-DD HH:mm]
- 访谈人：[姓名]

## 访谈内容
### 问题1：[问题]
回答：[回答]

## 需求要点
- [要点1]

## 后续行动
- [行动1]
```

## Quick Reference

| 操作 | 说明 |
|------|------|
| 识别来源 | 业务部门、技术团队、用户、管理层、监管 |
| 收集方法 | 访谈、问卷、文档分析、观察、头脑风暴 |
| 需求池维护 | 去重 -> 分类 -> 编号 -> 初评 |

## Quality Checklist

- [ ] 需求来源全面覆盖
- [ ] 收集方法多样互补
- [ ] 记录完整准确
- [ ] 需求池分类清晰、编号唯一

## Common Mistakes

- 只收集业务部门需求，忽略终端用户和外部监管
- 访谈缺少结构化问题，导致信息遗漏
- 需求池未去重，同一需求重复出现
- 需求描述模糊，缺少可验证的验收标准
