## Overview

将分析后的需求编写成标准化的需求规格说明书（SRS），包含功能需求、非功能需求、接口需求和用例文档。

## When to Use

- 需求分析完成，需要输出正式的SRS文档
- 需要编写用例文档描述系统行为
- 需要建立需求跟踪矩阵实现可追溯性
- 需要为开发团队提供明确的需求基线

## Core Pattern

| 阶段 | 产出 |
|------|------|
| 文档结构设计 | 确定SRS章节结构和编写规范 |
| 需求描述 | 功能需求、非功能需求、接口需求 |
| 用例编写 | 识别参与者、编写用例描述 |
| 跟踪矩阵 | 建立需求编号和跟踪关系 |

## Implementation

1. **文档结构设计** - 设计SRS结构，定义章节内容，确定编写规范
2. **需求描述** - 编写功能需求、非功能需求、接口需求
3. **用例编写** - 识别参与者，编写用例描述（前置条件、主成功场景、扩展场景）
4. **跟踪矩阵** - 建立需求编号，建立跟踪关系，维护矩阵

## Templates

### SRS模板

```markdown
# 需求规格说明书 (SRS)

## 1. 引言
### 1.1 目的 / 1.2 范围 / 1.3 术语定义

## 2. 总体描述
### 2.1 产品前景 / 2.2 用户特征 / 2.3 假设与依赖

## 3. 功能需求
### 3.x 功能模块N
#### 需求描述 / 输入 / 处理 / 输出

## 4. 非功能需求
### 性能需求 / 安全需求 / 可用性需求

## 5. 接口需求
### 用户接口 / 硬件接口 / 软件接口

## 6. 数据需求
### 数据模型 / 数据字典

## 7. 附录
### 需求跟踪矩阵
```

### 用例文档模板

```markdown
# 用例文档

## 用例描述
### UC1：用例名称
- **用例编号**：UC-001
- **参与者**：[参与者]
- **前置条件**：[前置条件]
- **后置条件**：[后置条件]
- **主成功场景**：
  1. [步骤1]
  2. [步骤2]
- **扩展场景**：
  - 2a. [扩展描述]
- **特殊需求**：[特殊需求]
```

## Quick Reference

| 操作 | 说明 |
|------|------|
| SRS结构 | 引言 -> 总体描述 -> 功能需求 -> 非功能需求 -> 接口 -> 数据 -> 附录 |
| 用例要素 | 编号、参与者、前置条件、主场景、扩展场景、特殊需求 |
| 跟踪矩阵 | 需求编号 <-> 设计元素 <-> 测试用例 |

## Quality Checklist

- [ ] SRS结构完整，覆盖所有章节
- [ ] 需求描述清晰、无歧义
- [ ] 用例覆盖所有功能场景
- [ ] 跟踪矩阵准确，每条需求可追溯

## Common Mistakes

- SRS缺少非功能需求章节，导致性能、安全需求遗漏
- 用例只写主成功场景，忽略扩展场景和异常路径
- 需求描述使用模糊词汇（"快速"、"友好"），缺少可量化指标
- 跟踪矩阵未维护，需求变更后矩阵与实际脱节
