## Overview

对收集的需求进行深入分析，确定可行性、优先级和依赖关系，为需求规格化提供依据。

## When to Use

- 需求池已建立，需要评估各需求的可行性
- 需要对需求进行优先级排序（P0-P3）
- 需要识别需求间的依赖和冲突
- 需要输出分析报告供后续规格化使用

## Core Pattern

| 分析维度 | 关键动作 |
|----------|----------|
| 可行性分析 | 从技术、经济、操作、时间四个维度评估 |
| 优先级评估 | 基于业务价值、技术复杂度、风险、依赖加权打分 |
| 依赖分析 | 识别需求间、系统间、资源间的依赖关系 |
| 冲突检测 | 检测需求矛盾、资源冲突、时间冲突 |

## Implementation

1. **可行性分析** - 评估技术可行性、经济可行性、操作可行性、时间可行性
2. **优先级评估** - 按业务价值(40%)、技术复杂度(30%)、风险程度(20%)、依赖关系(10%)加权计算总分
3. **依赖分析** - 梳理需求间依赖、系统间依赖、资源依赖
4. **冲突检测** - 检测需求矛盾、资源冲突、时间冲突并提出解决方案

## Templates

### 优先级矩阵模板

```markdown
# 优先级矩阵

## 评估维度
| 维度 | 权重 | 说明 |
|------|------|------|
| 业务价值 | 40% | 对业务的贡献度 |
| 技术复杂度 | 30% | 实现难度 |
| 风险程度 | 20% | 风险大小 |
| 依赖关系 | 10% | 依赖多少 |

## 需求优先级
| 编号 | 需求描述 | 业务价值 | 技术复杂度 | 风险 | 依赖 | 总分 | 优先级 |
|------|----------|----------|------------|------|------|------|--------|
| REQ-001 | [描述] | 8 | 5 | 3 | 2 | 6.1 | P0 |

## 优先级定义
- P0（必须有）：核心功能，必须实现
- P1（应该有）：重要功能，应该实现
- P2（可以有）：次要功能，可以实现
- P3（暂缓）：低优先级，后续考虑
```

### 依赖关系图模板

```markdown
# 依赖关系图

## 依赖说明
| 需求 | 依赖需求 | 依赖类型 | 说明 |
|------|----------|----------|------|
| REQ-003 | REQ-001 | 强依赖 | 必须先实现 |
| REQ-003 | REQ-002 | 强依赖 | 必须先实现 |
```

## Quick Reference

| 操作 | 说明 |
|------|------|
| 可行性评估 | 技术 + 经济 + 操作 + 时间 |
| 优先级计算 | 价值40% + 复杂度30% + 风险20% + 依赖10% |
| 依赖类型 | 强依赖（阻塞）、弱依赖（建议） |
| 冲突类型 | 需求矛盾、资源冲突、时间冲突 |

## Quality Checklist

- [ ] 可行性分析覆盖四个维度
- [ ] 优先级评估有量化依据
- [ ] 依赖关系明确标注强/弱依赖
- [ ] 所有冲突已识别并有解决方案

## Common Mistakes

- 优先级评估仅凭主观判断，缺少量化维度
- 忽略需求间隐式依赖，导致实施阶段阻塞
- 冲突检测不充分，需求矛盾遗留到开发阶段
- 可行性分析只看技术维度，忽略经济和时间约束
