## Overview

管理需求变更全流程，从变更请求、影响分析、审批到实施和验证，确保变更可控、可追溯。

## When to Use

- 干系人提出需求变更请求
- 需要评估变更对功能、进度、成本、风险的影响
- 变更审批通过后需要更新SRS和跟踪矩阵
- 需要维护变更记录实现可追溯

## Core Pattern

| 阶段 | 关键动作 |
|------|----------|
| 变更请求 | 接收请求、记录原因、初步评估 |
| 影响分析 | 分析功能、进度、成本、风险影响 |
| 变更审批 | 提交变更委员会，做出审批决定 |
| 变更实施 | 更新文档、通知人员、更新矩阵 |
| 变更验证 | 验证实施效果，关闭变更记录 |

## Implementation

1. **变更请求** - 接收变更请求，记录变更原因，初步评估影响范围
2. **影响分析** - 分析对功能、进度、成本、风险的影响，形成影响分析报告
3. **变更审批** - 提交变更委员会，评估变更必要性，做出批准/驳回/有条件批准决定
4. **变更实施** - 更新需求文档，通知相关人员，更新跟踪矩阵
5. **变更验证** - 验证变更实施效果，确认变更生效，关闭变更记录

## Templates

### 变更请求模板

```markdown
# 需求变更请求

## 基本信息
- 变更编号：[CR-XXX]
- 提出人：[姓名]
- 提出日期：[YYYY-MM-DD]
- 变更类型：新增/修改/删除

## 变更描述
### 原需求
[原需求描述]

### 变更内容
[变更内容描述]

### 变更原因
[变更原因]

## 影响分析
### 功能影响 / 进度影响 / 成本影响 / 风险影响

## 审批
- [ ] 批准 / [ ] 驳回 / [ ] 有条件批准
审批人：_________ 日期：_________
```

### 变更记录模板

```markdown
# 变更记录

| 变更编号 | 变更内容 | 提出人 | 审批人 | 审批日期 | 实施日期 | 状态 |
|----------|----------|--------|--------|----------|----------|------|
| CR-001 | [内容] | [姓名] | [姓名] | [日期] | [日期] | 已完成 |
```

## Quick Reference

| 操作 | 说明 |
|------|------|
| 变更流程 | 请求 -> 影响分析 -> 审批 -> 实施 -> 验证 |
| 影响维度 | 功能 + 进度 + 成本 + 风险 |
| 审批结果 | 批准 / 驳回 / 有条件批准 |
| 实施动作 | 更新文档 + 通知人员 + 更新矩阵 |

## Quality Checklist

- [ ] 变更流程规范，每步有记录
- [ ] 影响分析覆盖功能、进度、成本、风险
- [ ] 审批记录完整，有明确结论
- [ ] 变更可追溯，记录编号贯穿全流程

## Common Mistakes

- 跳过影响分析直接实施变更，导致连锁问题
- 变更实施后未更新跟踪矩阵，矩阵与实际脱节
- 变更记录不完整，缺少审批人或审批日期
- 只更新SRS不通知相关干系人，导致信息不对称
