## Overview

对需求规格说明书和用例文档进行系统化验证，确保需求完整性、一致性、可验证性和可追溯性。

## When to Use

- SRS文档编写完成，需要进行质量评审
- 需要验证需求是否覆盖所有业务场景
- 需要检查需求间是否存在矛盾或遗漏
- 需要确认需求可测试、可追溯

## Core Pattern

| 验证维度 | 检查要点 |
|----------|----------|
| 完整性 | 功能、非功能、接口、数据需求是否齐全 |
| 一致性 | 需求间无矛盾，术语使用统一 |
| 可验证性 | 每条需求有明确验收标准，可设计测试用例 |
| 可追溯性 | 需求来源、依赖、变更均可追溯 |

## Implementation

1. **完整性验证** - 检查功能需求、非功能需求、接口需求、数据需求是否完整覆盖
2. **一致性验证** - 检查需求间一致性、术语使用一致性、描述一致性
3. **可验证性验证** - 确认需求可测试、验收标准明确、测试用例可设计
4. **可追溯性验证** - 确认需求来源可追溯、依赖可追溯、变更可追溯

## Quick Reference

| 操作 | 说明 |
|------|------|
| 完整性 | 功能 + 非功能 + 接口 + 数据需求全覆盖 |
| 一致性 | 术语统一、需求间无矛盾 |
| 可验证性 | 每条需求有验收标准和测试方法 |
| 可追溯性 | 来源、依赖、变更三向可追溯 |

## Quality Checklist

- [ ] 验证覆盖四个维度（完整性、一致性、可验证性、可追溯性）
- [ ] 问题识别准确，严重程度分级合理
- [ ] 验证结论明确（通过/有条件通过/不通过）
- [ ] 改进建议具体可行

## Common Mistakes

- 只验证完整性，忽略一致性和可追溯性
- 问题清单缺少严重程度分级，所有问题同等对待
- 验证结论模糊，不给出明确通过/不通过判断
- 验证后未跟踪问题闭环，问题清单无人跟进
