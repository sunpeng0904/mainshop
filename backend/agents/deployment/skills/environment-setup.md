# 环境配置 Skill

配置稳定可靠的部署环境，确保基础设施满足应用运行要求。

## When to Use

- 需要搭建新的部署环境（开发/测试/预发/生产）
- 需要配置服务器、中间件、网络等基础设施
- 需要验证现有环境配置是否满足要求
- 需要编写环境文档和配置清单

**Do NOT use when:**
- 环境已就绪，仅需部署应用（使用 deploy-execute）
- 仅需要环境检查而非完整配置

## Core Pattern

### Before

```markdown
需求来了 → 临时申请资源 → 手动配置 → 缺少文档 → 难以复现
```

### After

```markdown
环境规划 → 资源申请 → 标准化配置 → 环境验证 → 文档归档
```

## Quick Reference

| 操作 | 说明 | 要点 |
|------|------|------|
| 环境规划 | 确定类型、资源、网络架构 | 区分开发/测试/预发/生产 |
| 环境搭建 | 申请资源、安装软件、配置参数 | 遵循最小权限原则 |
| 环境验证 | 检查配置、验证功能、测试性能 | 每项必须有验证记录 |
| 环境文档 | 编写文档、记录配置、维护清单 | 文档与实际配置保持一致 |

## Implementation

### Step 1: 环境规划

- 确定环境类型（开发/测试/预发/生产）
- 确定资源需求（服务器规格、数量）
- 确定网络架构（子网、安全组、负载均衡）

### Step 2: 环境搭建

- 申请服务器资源并分配IP
- 安装操作系统和中间件（JDK、Nginx、Redis、MySQL等）
- 配置系统参数、中间件参数、安全参数

### Step 3: 环境验证

- 检查环境配置是否符合规范
- 验证环境功能是否正常（网络连通性、服务可用性）
- 测试环境性能是否达标

### Step 4: 环境文档

- 编写环境配置文档，包含服务器、软件、网络、安全配置
- 记录所有配置参数和密码（密码需加密存储）
- 维护环境清单，定期更新

## Common Mistakes

| 错误 | 原因 | 修正 |
|------|------|------|
| 环境配置缺少文档 | 后续维护困难，无法复现 | 每次配置变更必须更新文档 |
| 安全配置不完善 | 存在安全隐患 | 遵循最小权限原则，配置防火墙和SSL |
| 监控配置遗漏 | 问题无法及时发现 | 必须配置CPU、内存、磁盘、日志监控 |
| 开发/生产环境混用 | 数据泄露风险 | 严格隔离不同环境 |

## Quality Checklist

- [ ] 环境配置正确，与规划一致
- [ ] 安全配置完善，防火墙和SSL已配置
- [ ] 监控配置完整，关键指标已覆盖
- [ ] 文档记录详细，与实际环境一致
