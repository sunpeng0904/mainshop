# 上线验证 Skill

验证系统上线后正常运行，确保业务可用并生成上线报告。

## When to Use

- 部署完成后，需要验证系统是否正常运行
- 需要完成功能、性能、安全、数据等多维度验证
- 需要生成上线报告并签字确认
- 需要确认系统是否可以正式对外发布

**Do NOT use when:**
- 部署尚未完成（使用 deploy-execute）
- 仅需要回滚而非上线确认（使用 rollback）

## Core Pattern

### Before

```markdown
部署完成 → 简单检查 → 直接上线 → 用户发现问题
```

### After

```markdown
部署完成 → 功能验证 → 性能验证 → 安全验证 → 数据验证 → 签字确认 → 正式发布
```

## Quick Reference

| 操作 | 说明 | 要点 |
|------|------|------|
| 功能验证 | 核心功能、业务流程 | 覆盖所有核心业务场景 |
| 性能验证 | 响应时间、并发、TPS | 与基线对比，不劣化 |
| 安全验证 | 权限、数据加密、接口鉴权 | 不可跳过安全验证 |
| 数据验证 | 数据迁移、一致性、关联关系 | 数据必须完整正确 |
| 上线确认 | 生成报告、签字、发布 | 需三方签字确认 |

## Implementation

### Step 1: 验证准备

- 制定验证计划，明确验证范围和标准
- 准备验证数据和测试用例
- 分配验证人员（技术、业务、运维）

### Step 2: 功能验证

- 验证核心功能（登录、查询、新增、修改、删除）
- 验证业务流程（完整业务链路）
- 验证数据正确性（数据展示、计算、导出）

### Step 3: 性能验证

- 验证响应时间（目标：<200ms）
- 验证并发能力（目标：1000并发）
- 验证TPS（目标：500 TPS）
- 验证错误率（目标：<0.1%）

### Step 4: 安全与数据验证

- 验证权限控制（功能权限、数据权限）
- 验证数据安全（加密、脱敏）
- 验证接口安全（鉴权、防重放）
- 验证数据迁移完整性
- 验证数据一致性

### Step 5: 上线确认

- 生成上线报告，汇总所有验证结果
- 签字确认（技术负责人、业务负责人、运维负责人）
- 正式对外发布

## Common Mistakes

| 错误 | 原因 | 修正 |
|------|------|------|
| 跳过安全验证 | 认为功能正常即可 | 安全验证不可跳过 |
| 性能验证不充分 | 仅测试单个接口 | 需测试完整业务链路和并发场景 |
| 数据验证遗漏 | 仅检查新增数据 | 需验证迁移数据、关联数据、历史数据 |
| 签字确认不完整 | 流程不规范 | 必须三方签字（技术、业务、运维） |
| 上线报告缺失 | 忙于处理问题 | 上线报告是交付物，必须生成 |

## Quality Checklist

- [ ] 验证覆盖全面，功能、性能、安全、数据均已验证
- [ ] 验证结果准确，每项有实际结果和状态
- [ ] 问题处理及时，所有问题已记录并有处理方案
- [ ] 签字确认完整，技术、业务、运维三方已签字
