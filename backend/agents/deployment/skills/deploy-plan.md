# 部署计划 Skill

制定详细的部署方案，确保部署过程可控、可回滚、可追溯。

## When to Use

- 测试报告已通过，需要制定正式部署方案
- 需要评估部署风险并制定应对措施
- 需要编制部署时间表和检查清单
- 需要制定回滚方案和应急预案

**Do NOT use when:**
- 测试尚未完成，部署条件不成熟
- 仅需要执行已有部署方案（使用 deploy-execute）

## Core Pattern

### Before

```markdown
测试通过 → 直接部署 → 遇到问题才处理
```

### After

```markdown
测试通过 → 风险评估 → 方案制定 → 方案评审 → 按方案执行
```

## Quick Reference

| 操作 | 说明 | 要点 |
|------|------|------|
| 部署评估 | 评估风险、确定时间和人员 | 风险高时需增加审批 |
| 方案制定 | 制定步骤、回滚方案、应急预案 | 每步必须可回滚 |
| 检查清单 | 部署前/中/后三阶段检查 | 不可跳过任何检查项 |
| 方案评审 | 完整性、可行性、风险评估 | 需技术负责人审批 |

## Implementation

### Step 1: 部署评估

- 评估部署风险等级（高/中/低）
- 确定部署时间窗口（建议低峰期）
- 确定部署人员和审批人员

### Step 2: 方案制定

- 制定详细部署步骤，每步标注预期时间
- 制定回滚方案，明确回滚触发条件
- 制定应急预案，识别风险并制定应对措施

### Step 3: 检查清单

- 部署前：代码冻结、测试通过、审批通过、通知相关人员
- 部署中：按步骤执行、记录过程、遇到问题暂停
- 部署后：服务启动正常、接口调用正常、数据验证正确、性能指标正常

### Step 4: 方案评审

- 方案完整性检查：所有步骤和检查项是否齐全
- 方案可行性检查：步骤是否可执行、时间是否合理
- 方案风险评估：风险识别是否充分、应对措施是否有效

## Common Mistakes

| 错误 | 原因 | 修正 |
|------|------|------|
| 跳过风险评估直接部署 | 低估风险导致问题频发 | 部署前必须完成风险评估 |
| 回滚方案缺失或不可用 | 无法快速恢复 | 回滚方案必须经过验证 |
| 检查清单项不完整 | 遗漏关键检查点 | 使用标准检查清单模板 |
| 部署时间选择高峰时段 | 影响用户使用 | 选择业务低峰期部署 |

## Quality Checklist

- [ ] 方案完整详细，涵盖所有变更内容
- [ ] 步骤清晰可行，每步有预期时间
- [ ] 回滚方案有效，已验证可执行
- [ ] 风险评估充分，应对措施明确
- [ ] 检查清单齐全，覆盖部署前/中/后
