# 部署执行 Skill

按照部署方案执行部署操作，确保每步可追溯、可验证。

## When to Use

- 部署方案已审批，需要执行部署
- 需要记录部署过程和结果
- 需要在部署后验证服务状态
- 部署过程中遇到问题需要记录和处理

**Do NOT use when:**
- 部署方案尚未制定（使用 deploy-plan）
- 需要回滚而非部署（使用 rollback）

## Core Pattern

### Before

```markdown
方案审批 → 直接上线 → 遇到问题临时处理 → 无记录
```

### After

```markdown
部署前检查 → 按步骤执行 → 每步记录 → 部署验证 → 生成报告
```

## Quick Reference

| 操作 | 说明 | 要点 |
|------|------|------|
| 部署前检查 | 环境、代码包、配置、备份 | 任何一项不通过则暂停 |
| 部署执行 | 备份→停止→部署→启动 | 按方案步骤严格执行 |
| 部署验证 | 服务状态、功能、日志 | 验证通过才算部署成功 |
| 部署记录 | 记录过程、结果、问题 | 记录必须真实完整 |

## Implementation

### Step 1: 部署前检查

- 检查环境状态是否正常
- 检查代码包是否完整
- 检查配置文件是否正确
- 确认数据库备份已完成

**任何一项检查不通过，暂停部署并通知相关人员。**

### Step 2: 部署执行

1. 备份当前版本（代码、配置、数据库）
2. 停止服务
3. 部署新版本（替换代码、更新配置、执行数据库变更）
4. 启动服务

每步记录开始时间、结束时间、执行结果。

### Step 3: 部署验证

- 检查服务状态（进程、端口、日志）
- 验证功能正常（核心接口调用）
- 检查日志无异常错误
- 验证性能指标正常

### Step 4: 部署记录

- 记录部署过程（每步执行情况）
- 记录部署结果（成功/失败/部分成功）
- 记录遇到的问题及处理方式
- 生成部署报告并签字确认

### 部署执行规范

```markdown
## 部署前要求
- [ ] 部署方案已审批
- [ ] 测试报告已通过
- [ ] 代码已冻结
- [ ] 通知已发送

## 部署中要求
- [ ] 按步骤执行
- [ ] 记录执行过程
- [ ] 遇到问题暂停
- [ ] 保持沟通畅通

## 部署后要求
- [ ] 验证服务状态
- [ ] 验证功能正常
- [ ] 记录部署结果
- [ ] 发送部署通知
```

## Common Mistakes

| 错误 | 原因 | 修正 |
|------|------|------|
| 跳过部署前检查 | 节省时间 | 检查项必须全部通过才能继续 |
| 不记录执行过程 | 事后无法追溯 | 每步必须记录时间和结果 |
| 遇到异常继续执行 | 侥幸心理 | 遇到任何异常立即暂停并评估 |
| 忘记备份 | 操作失误 | 备份是第一步，不可跳过 |
| 部署后不验证 | 认为启动即成功 | 必须验证服务状态和功能 |

## Quality Checklist

- [ ] 执行过程规范，按方案步骤执行
- [ ] 记录完整准确，每步有时间戳和结果
- [ ] 验证充分有效，覆盖服务、功能、性能
- [ ] 问题处理及时，异常情况已记录和处理
