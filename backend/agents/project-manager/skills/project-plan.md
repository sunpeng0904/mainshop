# 项目计划 Skill

## Overview

基于项目章程，制定详细的项目执行计划，包括WBS分解、进度计划和资源计划。

## When to Use

- 项目章程已批准，需要制定执行计划
- 需要进行WBS工作分解
- 需要编制进度计划和资源分配方案
- 项目计划需要更新或调整

## Core Pattern

| 阶段 | 输入 | 输出 |
|------|------|------|
| WBS分解 | 项目章程、范围说明 | WBS工作分解结构 |
| 进度计划 | WBS、依赖关系 | 里程碑、甘特图 |
| 资源计划 | 进度计划、团队成员 | 资源分配表 |

## Implementation

### 1. WBS分解
- 分解项目工作包
- 确定工作包层级
- 明确交付物

### 2. 进度计划
- 估算工作量
- 确定依赖关系
- 制定时间表

### 3. 资源计划
- 分配人力资源
- 分配物质资源
- 确定资源日历

### 4. 质量检查
- 检查计划完整性
- 检查资源合理性
- 生成审核报告

## Templates

### WBS模板

```markdown
# WBS分解

## 1. 项目管理
- 1.1 项目启动
- 1.2 项目计划
- 1.3 项目监控
- 1.4 项目收尾

## 2. 需求阶段
- 2.1 需求收集
- 2.2 需求分析
- 2.3 需求评审

## 3. 设计阶段
- 3.1 架构设计
- 3.2 详细设计
- 3.3 设计评审

## 4. 开发阶段
- 4.1 环境搭建
- 4.2 编码开发
- 4.3 代码评审

## 5. 测试阶段
```

## Quality Checklist

- [ ] WBS分解完整
- [ ] 工作量估算合理
- [ ] 资源分配均衡
- [ ] 依赖关系正确
- [ ] 里程碑可行

## Quick Reference

| 操作 | 说明 |
|------|------|
| WBS分解 | 按阶段逐层分解到工作包 |
| 工作量估算 | 使用类比或三点估算法 |
| 依赖关系 | FS/FF/SS/SF四种类型 |
| 资源分配 | 避免资源过载 |
| 里程碑 | 关键节点设置检查点 |

## Common Mistakes

- WBS分解粒度过粗，遗漏关键工作包
- 工作量估算过于乐观，未留缓冲
- 资源分配不均衡，存在过载风险
- 依赖关系未正确识别，导致计划不可行
- 里程碑设置不合理，缺乏可行性

## Dependencies

- 项目启动技能（project-init）
- 进度跟踪技能（progress-track）
