## Overview

有效管理缺陷生命周期，从发现到关闭全流程跟踪，确保缺陷得到及时修复和验证。

## When to Use

- 测试执行中发现缺陷，需要记录和提交时
- 需要跟踪缺陷修复进度时
- 需要验证缺陷修复结果时
- 需要统计缺陷分布和趋势时

## Core Pattern

| 场景 | 做法 |
|------|------|
| 发现缺陷 | 记录复现步骤、预期/实际结果，分配严重程度 |
| 跟踪修复 | 按状态流转跟踪，定期检查进度 |
| 验证修复 | 按原复现步骤验证，通过则关闭 |
| 验证失败 | 重新打开，补充信息后重新分配 |

## Implementation

1. **缺陷发现** - 识别缺陷现象，记录复现步骤，分类严重程度
2. **缺陷分析** - 分析缺陷根因，评估影响范围，确定修复优先级
3. **缺陷跟踪** - 分配责任人，跟踪修复进度，验证修复结果
4. **缺陷关闭** - 验证修复通过，更新缺陷状态，关闭缺陷记录

### 缺陷状态流转

| 当前状态 | 触发条件 | 下一状态 |
|----------|----------|----------|
| 新建 | 确认缺陷 | 确认 |
| 新建 | 非缺陷 | 拒绝 |
| 确认 | 分配开发 | 分配 |
| 分配 | 开始修复 | 修复中 |
| 修复中 | 修复完成 | 已修复 |
| 已修复 | 测试验证 | 验证中 |
| 验证中 | 验证通过 | 关闭 |
| 验证中 | 验证失败 | 重新打开 |
| 重新打开 | 重新分配 | 分配 |

## Quick Reference

| 操作 | 说明 |
|------|------|
| 严重程度 | 致命(系统崩溃)、严重(功能不可用)、一般(功能异常)、轻微(界面问题) |
| 优先级 | P0(立即修复)、P1(尽快修复)、P2(正常修复)、P3(低优先级) |
| 状态流转 | 新建→确认→分配→修复中→已修复→验证中→关闭 |
| 验证要点 | 按原复现步骤验证，确认修复无副作用 |

## Common Mistakes

- 缺陷标题不清晰，无法快速定位问题
- 复现步骤不完整，开发无法复现
- 严重程度和优先级评估不准确
- 验证时未按原步骤执行，遗漏回归问题
- 缺陷信息不完整，缺少环境和版本信息
