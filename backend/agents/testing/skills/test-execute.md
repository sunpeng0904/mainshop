## Overview

执行测试用例，如实记录测试结果，统计执行数据，为测试报告提供准确的执行依据。

## When to Use

- 测试用例评审通过后，需要开始执行测试时
- 需要记录测试执行结果和发现的问题时
- 需要统计测试通过率和执行进度时
- 需要生成测试执行报告时

## Core Pattern

| 场景 | 做法 |
|------|------|
| 用例执行 | 按步骤操作，如实记录实际结果 |
| 发现缺陷 | 立即记录，关联用例编号，提交缺陷 |
| 环境问题 | 记录问题详情，标记阻塞状态 |
| 执行中断 | 记录中断原因，恢复后继续执行 |

## Implementation

1. **测试准备** - 环境检查、数据准备、工具准备
2. **测试执行** - 按用例步骤执行，记录执行结果，记录发现的问题
3. **缺陷记录** - 记录缺陷详情，分配缺陷责任人，跟踪缺陷状态
4. **结果汇总** - 统计测试结果，分析测试数据，生成执行报告

### 测试执行规范

| 阶段 | 检查项 |
|------|--------|
| 执行前 | 环境检查通过、数据准备完成、工具准备完成、用例熟悉完成 |
| 执行中 | 按步骤执行、如实记录、及时记录问题、保持环境稳定 |
| 执行后 | 结果统计完成、缺陷记录完成、环境恢复完成、报告生成完成 |

## Quick Reference

| 操作 | 说明 |
|------|------|
| 记录结果 | 通过/失败/阻塞/跳过，如实记录 |
| 关联缺陷 | 失败用例必须关联缺陷编号 |
| 统计数据 | 按模块、优先级、执行人分别统计 |
| 环境标记 | 区分功能问题和环境问题 |

## Common Mistakes

- 修改测试用例以匹配实际结果
- 跳过测试步骤，凭经验判断结果
- 忽略异常现象，不记录不报告
- 隐瞒测试问题，影响报告准确性
- 缺陷记录不完整，缺少复现步骤
