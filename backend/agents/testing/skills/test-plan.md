## Overview

制定全面的测试计划，指导测试活动的开展，确保测试目标明确、范围清晰、策略合理。

## When to Use

- 收到需求文档和设计文档，需要规划测试活动时
- 项目启动阶段，需要确定测试范围和策略时
- 需要评估测试风险和资源需求时
- 需要制定测试进度和准入准出标准时

## Core Pattern

| 场景 | 做法 |
|------|------|
| 需求已明确 | 直接分析需求，确定测试范围和重点 |
| 需求不明确 | 先与需求方确认，再制定计划 |
| 资源有限 | 优先覆盖核心功能，按风险排序 |

## Implementation

1. **需求分析** - 分析测试需求，确定测试范围，识别测试重点
2. **策略制定** - 确定测试类型（功能/性能/安全）、测试方法（黑盒/白盒/灰盒）、测试工具
3. **计划制定** - 制定测试进度，分配测试资源，确定准入准出条件
4. **风险评估** - 识别测试风险，制定应对措施，确定应急预案

## Quick Reference

| 操作 | 说明 |
|------|------|
| 确定范围 | 核心功能 > 重要功能 > 边缘功能 |
| 选择策略 | 按风险等级选择测试类型和深度 |
| 分配资源 | 按模块复杂度和风险分配人员 |
| 制定进度 | 预留20%缓冲时间应对风险 |

## Common Mistakes

- 测试范围过大，未聚焦核心功能
- 测试策略未考虑项目实际约束
- 进度计划过紧，未预留缓冲时间
- 风险评估不充分，缺少应对措施
- 准入准出条件模糊，缺乏可执行性
