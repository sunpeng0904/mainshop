## Overview

生成全面的测试报告，总结测试活动，分析测试数据，为发布决策提供依据。

## When to Use

- 测试执行完成后，需要总结测试活动时
- 需要向项目干系人汇报测试情况时
- 需要评估产品质量和发布风险时
- 需要提供发布建议时

## Core Pattern

| 场景 | 做法 |
|------|------|
| 数据完整 | 直接统计分析，生成报告 |
| 数据不完整 | 补充收集数据后再生成报告 |
| 发现阻塞问题 | 在报告中标注风险，提供发布建议 |
| 多轮测试 | 汇总各轮数据，分析趋势变化 |

## Implementation

1. **数据收集** - 收集测试数据、缺陷数据和执行记录
2. **数据分析** - 分析测试覆盖率、缺陷分布和测试趋势
3. **报告生成** - 生成测试报告、统计图表和测试总结
4. **报告评审** - 检查报告完整性、准确性和可读性

## Quick Reference

| 操作 | 说明 |
|------|------|
| 统计指标 | 通过率、缺陷密度、覆盖率、遗留缺陷数 |
| 发布判断 | 无致命缺陷、通过率>95%、遗留缺陷可控 |
| 风险标注 | 致命/严重缺陷未修复必须标注 |
| 改进建议 | 基于缺陷分析，提出流程和方法改进建议 |

## Common Mistakes

- 数据统计不准确，与实际执行记录不一致
- 缺陷分析不深入，仅罗列数据未分析原因
- 结论主观偏颇，未客观反映测试情况
- 建议缺乏可操作性，过于笼统
- 遗漏环境问题和阻塞问题的说明
