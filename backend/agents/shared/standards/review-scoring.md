# 审核评分标准

## 评分维度

### 1. 完整性 (25分)

| 分数段 | 标准 |
|--------|------|
| 21-25 | 所有必填项完整，无遗漏 |
| 16-20 | 大部分完整，有1-2处小遗漏 |
| 11-15 | 基本完整，有3-5处遗漏 |
| 6-10 | 较多遗漏，需要补充 |
| 0-5 | 严重不完整，需要重新生成 |

### 2. 规范性 (25分)

| 分数段 | 标准 |
|--------|------|
| 21-25 | 完全符合中证规范 |
| 16-20 | 基本符合，有1-2处小偏差 |
| 11-15 | 部分符合，需要调整 |
| 6-10 | 较多不符合，需要修改 |
| 0-5 | 严重不符合，需要重做 |

### 3. 质量 (25分)

| 分数段 | 标准 |
|--------|------|
| 21-25 | 内容准确、逻辑清晰、无歧义 |
| 16-20 | 质量良好，有小问题 |
| 11-15 | 质量一般，需要改进 |
| 6-10 | 质量较差，需要大幅修改 |
| 0-5 | 质量不合格，需要重做 |

### 4. 可维护性 (25分)

| 分数段 | 标准 |
|--------|------|
| 21-25 | 结构清晰、易于维护、有扩展性 |
| 16-20 | 结构良好，基本可维护 |
| 11-15 | 结构一般，维护成本中等 |
| 6-10 | 结构较差，维护困难 |
| 0-5 | 结构混乱，需要重构 |

## 总分等级

| 分数段 | 等级 | 处理方式 |
|--------|------|----------|
| 90-100 | 优秀 | 可直接提交人工审核 |
| 70-89 | 良好 | 建议修改后提交 |
| 60-69 | 及格 | 需要修改后重新审核 |
| 0-59 | 不合格 | 需要重新生成 |

## 各阶段专项评分

### 项目管理阶段
- 项目目标明确性 (+5)
- 计划可执行性 (+5)
- 风险识别全面性 (+5)
- 资源分配合理性 (+5)
- 进度可控性 (+5)

### 需求阶段
- 需求完整性 (+5)
- 需求一致性 (+5)
- 需可验证性 (+5)
- 需求优先级合理性 (+5)
- 需求变更控制 (+5)

### 设计阶段
- 架构合理性 (+5)
- 技术选型适当性 (+5)
- 词根规范性 (+5)
- 安全设计 (+5)
- 性能设计 (+5)

### 开发阶段
- 代码规范性 (+5)
- 注释完整性 (+5)
- 架构层次符合性 (+5)
- 单元测试覆盖 (+5)
- 代码可读性 (+5)

### 测试阶段
- 测试覆盖率 (+5)
- 用例完整性 (+5)
- 缺陷发现能力 (+5)
- 回归测试 (+5)
- 测试报告质量 (+5)

### 部署阶段
- 部署方案完整性 (+5)
- 环境配置正确性 (+5)
- 回滚方案 (+5)
- 监控告警 (+5)
- 上线检查清单 (+5)
